# UX Reference Studio — 학습 모드 기능 명세서

버전 1.0 · 2026-10-15

## 1. 배경과 목적

AI 가 화면을 순식간에 만들어 주는 시대일수록, 기획자는 **화면을 논리적으로 직접 분석할 수 있어야** 한다. 이 도구는 레퍼런스 화면을 AI 로 분석해 주던 기존 기능 위에, 사용자가 **먼저 손으로 그리고(와이어프레임), 정보를 정리하고(IA), 이유를 적은 뒤(코멘트)** AI 결과와 비교해 보는 학습 루프를 얹는다. 결과물은 그대로 LinkedIn 학습 기록 글의 초안이 된다.

현직자 강의·답변과 강의 자료(UX/UI 프로세스: 요구사항 → 리서치 → 정책/기능 정의 → Spec/Resizing → IA/Depth → Wireframe → UI)에서 가져온 원칙을 기능으로 옮긴다.

## 2. 학습 원칙 → 기능 매핑

| 강의 내용 | 기능으로 옮긴 방식 |
| --- | --- |
| "버튼은 정보가 아니다. 정보와 컴포넌트는 구분해야 한다" | 내 IA 트리에는 **정보만** 넣는다. 버튼·탭·모달 같은 이름이 들어오면 린트 경고를 띄우고 "컴포넌트 보관함"으로 옮기게 한다. 와이어프레임 블록은 **정보 / 컴포넌트** 역할을 반드시 고른다. |
| "IA 의 원리는 정보의 서랍 정리. 특징으로 먼저 묶고 그 묶음을 넣는다" | 1~3 depth 트리 편집기 (들여쓰기/내어쓰기/순서 이동). 각 노드에 노출 조건을 적을 수 있다. |
| "btn 은 소문자로" | IA/블록 이름의 `BTN` 대문자 표기를 린트로 안내 |
| "컴포넌트가 보여야 와이어프레임을 칠 줄 아는 것" | 블록마다 컴포넌트 여부를 표시하고, 체크리스트에서 컴포넌트가 하나도 없으면 미완료로 표시 |
| "더미 텍스트 넣지 말고 내용을 넣어라" | 블록마다 **실제 문구(content)** 필드. lorem/더미/ㅇㅇ 등은 린트로 잡는다 |
| "손으로 그려도 디테일하게" | 피그마식 캔버스: 블록·텍스트·펜·핀 도구, 이동/리사이즈, 실행 취소, 확대/축소, 스크린샷 투명도, 12 컬럼 그리드 |
| 노출 항목/케이스 구분표, Sign up 과제의 State case | 블록마다 **노출 조건/상태 케이스** 입력 (한 줄에 하나) |
| Spec/Resizing (px, 컬럼, 브레이크포인트) | 선택한 블록의 실제 px 크기·위치 표시, 12 컬럼 그리드 오버레이, 캡처 폭 표시 |
| "데이터에서 시작하지 말고 문제에서 시작" / KPI 는 획득과 매출 | 레퍼런스마다 **문제 정의 카드**(문제·가설·타깃·KPI·근거) |
| "AI 가 못하는 영역은 디자인 시스템을 일관되게 구현하는 것" / 포트폴리오 = 논리의 가시화 | **AI 와 비교** 탭: 블록 일치율(IoU), IA 일치, "AI 화면의 특징 / 내 분석과 다른 점 / 개선 여지 / 근거" 작성 → LinkedIn 글 초안과 비교 이미지로 내보내기 |
| 리서치 → 산출물 순서 | AI 결과는 기본적으로 **가려 둔다**. 직접 그린 뒤 "AI 분석 공개"를 눌러야 AI 와이어프레임·분석·비교 탭이 열린다 |

## 3. 사용자 플로우

1. URL 분석 또는 스크린샷 업로드 → 레퍼런스 저장. AI 결과는 가려진 채 **내 와이어프레임** 탭으로 이동한다.
2. **내 와이어프레임**: 스크린샷 위에 블록을 그리고 라벨·종류·역할(정보/컴포넌트)·실제 문구·상태 케이스를 적는다. 궁금한 지점에는 핀을 꽂아 코멘트를 남긴다.
3. **내 IA**: 문제 정의 카드를 채우고, 정보만으로 1~3 depth 트리를 만든다. 린트 경고를 해결한다.
4. **AI 분석 공개** → AI 와이어프레임/분석 탭을 확인한다.
5. **비교·기록**: 블록/IA 일치 결과를 보고 비교 글(특징·차이·개선 여지·근거)을 쓴다. 체크리스트로 원칙을 점검한다.
6. **내보내기**: LinkedIn 초안(Markdown) 복사/저장, 비교 이미지(PNG) 저장. 오른쪽 코멘트 패널의 메모도 초안에 포함된다.

## 4. 기능 명세

### 4.1 내 와이어프레임 (탭 `draw`)

| ID | 기능 | 상세 | 수용 기준 |
| --- | --- | --- | --- |
| D-1 | 도구 | 선택(V) · 블록(R) · 텍스트(T) · 펜(P) · 핀(C). 단축키는 입력창 밖에서만 동작 | 도구 전환 즉시 커서/동작이 바뀐다 |
| D-2 | 블록 그리기 | 드래그로 사각형 생성. 좌표는 스크린샷 기준 % 로 저장해 AI 블록과 같은 좌표계 | 1% 미만 드래그는 무시, 생성 후 선택 도구로 복귀 |
| D-3 | 이동/리사이즈 | 선택한 블록·텍스트는 드래그 이동, 8 방향 핸들로 리사이즈. 펜·핀은 이동만 | 0~100% 범위를 벗어나지 않는다 |
| D-4 | 속성 편집 | 라벨, 종류(헤더/내비/히어로/…), 역할(정보/컴포넌트), 실제 문구, 노출 조건/상태 케이스, 연결 IA 노드, 메모 | 변경 즉시 자동 저장 (0.9 초 디바운스) |
| D-5 | 실측 정보 | 선택한 블록의 px 위치·크기 (캡처 폭 기준) 표시 | 스크린샷 크기에 비례해 계산 |
| D-6 | 캔버스 보조 | 확대/축소(50~200%), 스크린샷 투명도, 12 컬럼 그리드 | 스크린샷 없이도(투명도 0) 와이어프레임만 볼 수 있다 |
| D-7 | 실행 취소/다시 실행 | Ctrl+Z / Ctrl+Shift+Z(Ctrl+Y). 도형 추가·이동·삭제 단위 | 60 단계까지 |
| D-8 | 핀 코멘트 | 클릭한 지점에 번호 핀을 꽂고 텍스트를 적는다 | 핀은 비교 이미지·초안에 포함 |
| D-9 | 린트 | 문구 없음, 더미 문구, 컴포넌트 없음을 사이드 패널에 표시 | 체크리스트와 동일 기준 |
| D-10 | PNG 내보내기 | 스크린샷 + 내 도형을 합성해 PNG 저장 | 최대 폭 1600px |

### 4.2 내 IA (탭 `ia`)

| ID | 기능 | 상세 | 수용 기준 |
| --- | --- | --- | --- |
| I-1 | 문제 정의 카드 | 문제, 가설, 타깃 사용자, KPI(획득/매출 연결), 근거 데이터 | 체크리스트에서 문제·KPI 작성 여부 확인 |
| I-2 | 트리 편집 | 노드 추가(형제/하위), 이름·노출 조건 입력, 들여쓰기/내어쓰기, 위/아래 이동, 삭제(하위 포함) | depth 는 최대 3 |
| I-3 | 정보/컴포넌트 린트 | 컴포넌트 단어가 이름에 있으면 경고 + "컴포넌트로 옮기기". 옮기면 하위 노드는 상위로 붙는다 | 보관함의 컴포넌트는 트리에 보이지 않는다 |
| I-4 | 컴포넌트 보관함 | 트리 밖으로 뺀 컴포넌트 목록. 와이어프레임 블록 중 컴포넌트 역할인 것도 함께 보여 준다 | "정보로 되돌리기" 가능 |

### 4.3 AI 결과 가리기

| ID | 기능 | 상세 |
| --- | --- | --- |
| R-1 | 커버 | `study.revealed` 가 false 이면 AI 와이어프레임·AI 분석·비교·기록 탭에 커버 표시. 내 진행 상황(블록/IA 노드 수)과 "AI 분석 공개" 버튼 |
| R-2 | 코멘트 섹션 | 공개 전에는 코멘트 패널의 섹션 목록에 내 IA 노드만, 공개 후에는 AI 섹션도 함께 보인다 |

### 4.4 비교·기록 (탭 `compare`)

| ID | 기능 | 상세 | 수용 기준 |
| --- | --- | --- | --- |
| C-1 | 블록 비교 | 내 블록과 AI 블록을 IoU ≥ 0.4 로 1:1 매칭. 일치 / 내가 본 것 / AI 만 본 것 목록과 수치 | 스크린샷 위에 두 레이어를 겹쳐 표시, 각각 켜고 끌 수 있다 |
| C-2 | IA 비교 | 이름을 정규화해 포함 관계로 매칭. 일치 / 내 IA 에만 / AI IA 에만 | |
| C-3 | 비교 글 | AI 화면의 특징 · 내 분석과 다른 점 · 개선 여지 · 근거 (4 개 입력) | 자동 저장 |
| C-4 | 원칙 체크리스트 | 블록 5 개 이상, 모든 블록에 실제 문구, 더미 문구 없음, 컴포넌트 블록 있음, IA 에 컴포넌트 없음, IA 2 depth 이상, 상태 케이스 1 개 이상, 문제·KPI 작성, 비교 글 작성 | 자동 계산 |
| C-5 | LinkedIn 초안 | 레퍼런스·문제 정의·내 IA·컴포넌트·비교 수치·비교 글·코멘트를 Markdown 으로 생성. 복사 / .md 저장 | |
| C-6 | 비교 이미지 | 스크린샷 + AI 블록 + 내 블록 합성 PNG 저장 | |

### 4.5 저장

| ID | 기능 | 상세 |
| --- | --- | --- |
| S-1 | studies 테이블 | 레퍼런스당 1 행 (`reference_id` PK, `data` jsonb). Supabase 미설정 시 IndexedDB `studies` 스토어 |

## 5. 데이터 모델 (`study.data`)

```
{
  version: 1,
  revealed: boolean,                       // AI 결과 공개 여부
  drawing: {
    shapes: [
      { id, kind: 'block', x, y, w, h (%), label, type, role: 'info'|'component', content, states, ia_id, note },
      { id, kind: 'text',  x, y, w, h, text },
      { id, kind: 'pen',   points: [[x, y], ...], color }
    ],
    pins: [ { id, x, y, text, created_at } ]
  },
  ia: { nodes: [ { id, name, kind: 'info'|'component', parent_id, condition, note } ] },   // 배열 순서 = 형제 순서
  plan: { problem, hypothesis, target, kpi, evidence },
  compare: { ai_traits, my_view, improvement, evidence }
}
```

## 7. 비기능 요구사항

- 기존 파일 구조와 한국어 UI 유지. API 키·Supabase 정보는 코드에 넣지 않는다.
- 웹(Vercel)과 데스크톱(Electron) 모두 동일하게 동작한다 (학습 기록은 렌더러에서 직접 저장).
- 스크린샷 합성(PNG)은 브라우저 캔버스로 처리하며, Supabase 공개 URL 은 CORS 허용이므로 그대로 사용한다.

## 8. 이후 과제 (이번 범위 밖)

- 플로우차트(화면 간 이동) 그리기, 브레이크포인트별 와이어프레임
- 코멘트에 유형(관찰/질문/개선안/원칙) 태그
- 여러 레퍼런스를 묶은 학습 시리즈 내보내기
